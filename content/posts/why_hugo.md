> **2026-11 更新**：站点后来从 Hugo 迁到了 Next.js 静态导出，不过 Markdown 源文件、构建生成纯静态 HTML 再托管到 Cloudflare Pages 这套做法没变。下文记录的是最初切到 Hugo 时的想法。

## 从 WordPress 说起

早些年搭博客，大家最先想到的往往是 WordPress。它确实成熟，主题和插件生态都全，但自己用下来，后台绝大部分功能根本点不到，服务器和数据库却得一直开着，还要定期备份。

更磨人的是运维和迁移成本。PHP、MySQL 一样不能少，文章和配置全捆在数据库里，每次换服务器都要导出导入、核对字符编码、收拾图片路径和固定链接。默认情况下，每次有访客进来，服务器还得走一遍 PHP 和数据库查询，最后交到浏览器手里的无非是一张 HTML；就算配上页面缓存插件扛住流量，后台、PHP 和数据库也还是得一直在跑。我只是想找个地方写字，没必要顺带养一套动态后端。

## 换成 Hugo

拆开看，个人博客要的东西其实很简单：一组 Markdown 文件、一套页面模板，再加上 RSS。

换成 Hugo 之后，整个博客就是个纯静态文件夹。写文章就是开一个 `.md` 文件，直接放进 Git 仓库，提交记录顺带充当修改历史。Hugo 本身是个单文件二进制，不挑构建环境，本地几毫秒就能生成整站，分类、标签、RSS 都是原生支持，不用折腾额外插件。生成完直接扔给 Cloudflare Pages，没有服务器要维护，也不用担心数据库备份。以后真想换框架或换平台，把 Markdown 文件夹拷走就能重来。

## 静态 HTML 对爬虫和检索更友好

除了人之外，博客的访客还有搜索引擎爬虫、RSS 阅读器，以及这两年各家的 AI 抓取程序。

纯静态页对这些程序也很省心：URL 干净，正文全部在 HTML 源码里，不需要执行 JS 就能直接抓取全文，RSS 订阅源也是构建时一起生成的。至于仓库里的 Markdown 源文件，本身就是带标题层级的纯文本，丢给大模型解析也几乎没有格式损耗。

## 小结

切到 Hugo 以后，写作这件事轻了很多。以前要先登录后台、等富文本编辑器加载、来回调排版；现在只要新建一个 `.md` 文件，写完 `git push`，一两分钟后就能通过 CDN 看到更新。
