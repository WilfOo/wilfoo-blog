> **2026-11 更新**：站点改用 Next.js 重写后背景又换回了等高线，这篇文章记录的是 Hugo + PaperMod 时期那版毛玻璃背景的实现。

## 动机

[等高线背景](/posts/contour-map-background/)用了一阵子，想换个视觉风格。音乐播放器 SPlayer-Next 的界面给过我一个思路：把专辑封面铺开当背景并做大面积模糊，卡片以毛玻璃形式浮在上面。博客没有专辑封面，就用程序自己画一张。

动手前先理了几条要求：每次访问随机生成、窗口缩放时不换图；色调控制在深灰和藏青，压住花哨感；亮暗两套主题都得成立，切换时背景整幅跟着换；正文直接压在画布上，对比度必须能过 WCAG AA（4.5:1）；加一点克制的光标反馈，尽量控制开销，依旧不引外部依赖。

## 自己画一张「封面」

播放器的模糊背景是现成封面图加模糊。如果博客也去逐像素生成一整屏再模糊，计算量太重，所以把渲染分辨率降下来，让浏览器管线帮着柔焦：

```
低分辨率 canvas（长宽各取视口的 1/4）→ CSS 拉伸放大 → filter: blur(48px) → 固定底层
                                      ↑ 上采样自带柔焦    ↑ 抹平最后的块状感
```

| 做法 | 像素量（1440×900） | 模糊代价 |
| --- | --- | --- |
| 逐像素生成整屏 + 模糊 | ~130 万 | 每帧全屏运算 |
| 长宽 1/4（像素数 1/16）+ 拉伸 + blur | ~8.1 万 | 低一个多数量级 |

拉伸放大加上 `blur(48px)`，反而把低分辨率的棱角揉成了类似云雾的质感。

## 生成噪声与光斑

随机数和噪声函数直接沿用等高线那篇：`mulberry32` 种子随机加 2D simplex 噪声，页面加载时用 `(Date.now() ^ ((Math.random() * 0xffffffff) | 0)) >>> 0` 生成种子，和不同常量异或分别喂给噪声场与调色板，保证窗口缩放重绘时还是同一张图。

初始化时先离线生成一张静态「底纹」：每个像素采样 4 层 fBm，存进 `Float32Array`，之后重绘只查表不再重算。接着在画布上铺 7 团光斑，圆心、半径、摆动幅度、相位全部随机，每团再抽一个 0~1 的色调倾向（为了方便阅读，下面按对象结构示意；实际代码里把这些字段摊平进了几个 `Float64Array`，避免热循环里反复读对象属性）：

```js
var hue = Math.max(0, Math.min(1, rand() * 1.4 - 0.2)); // 0 偏灰、1 偏藏青
blobs.push({
  cx: rand() * w,  cy: rand() * h,
  r: (0.16 + 0.10 * rand()) * Math.max(w, h),
  str: 0.7 + 0.6 * rand(), // 强度
  hue: hue
});
```

绘制时遍历每像素到 7 团光斑的距离平方比 `q = (dx * dx + dy * dy) / r²`，落在圆内的按 `(1 - q)² * str` 权重（相当于对 `(d/r)²` 做二次衰减，既省掉了热循环里的 `Math.sqrt`，边缘过渡也更平顺）加权混色，再用静态噪声场调制亮度，叠出云絮纹理：

```js
var m = 1 + field[yy * w + xx] * (variant === 'light' ? 0.35 : 0.55);
col = [col[0] * m, col[1] * m, col[2] * m];
```

亮色模式下把调制幅度从 `0.55` 收小到 `0.35`：亮色正文是深色字直接压在背景上，纹理太重会抢字的可读性。

最后把边缘过渡直接画进像素里——按 L1 距离（`|nx| + |ny|`）从中心向外混向边缘底色：暗色主题向深黑压暗，亮色主题向浅灰白压淡。这样不用多挂一层遮罩 DOM，四周区域也会更干净。

## 光标跟随与节流

`pointermove` 事件只更新目标点，真正计算缓动放在 `requestAnimationFrame` 里按帧率无关的指数趋近推进：

```js
function frame(now) {
  var dt = Math.min(64, now - lastT);
  var k = 1 - Math.pow(0.0002, dt / 1000); // 帧率无关，60Hz 和 144Hz 手感一致
  cur.x += (target.x - cur.x) * k;
  if (moving) {
    if (now - lastPaint >= interval) { // 按实测耗时动态节流，不每帧重算整张画布
      paint(now / 1000, cur.x - 0.5, cur.y - 0.5, variantNow());
      lastPaint = now;
    }
    raf = requestAnimationFrame(frame);
  }
}
```

噪声场本身变化极慢，没必要按屏幕刷新率每帧重算整个 `ImageData`。实际实现会根据单次绘制实测耗时 `paintMs` 动态节流：指针跟随阶段大约每 `33~100ms` 重绘一次画布，空闲自动漂移阶段放宽到 `80~200ms`；只有随指针移动的柔光晕（`#noise-glass-glow`）逐帧更新 `translate3d`，纯走合成器。

行为分成几段：鼠标在窗口内时，光斑朝光标方向缓慢牵引，光晕跟着指针走，玻璃卡片背后能看到一点淡淡的蓝光流动；指针离开窗口且有精细指针（`pointer: fine`）时，切回两个不同频率正弦叠加的慢速漂移；`prefers-reduced-motion` 下只关闭自动漂移，保留用户主动移动光标时的跟随反馈——不少桌面环境关掉系统动画后就会触发这个媒体查询，全关的话交互感会直接消失。

另外记一个踩过的坑：第一版的首帧绘制依赖 rAF 循环，而循环要等第一次 `pointermove` 才启动，结果在触屏和无头浏览器里背景一片空白。后来改成 `init` 里无论如何先同步画一帧静态场，再把后续动画交给循环。

## 主题切换

PaperMod 切换亮暗主题只是修改 `html[data-theme]` 属性，CSS 变量能立即生效，但已经画进 canvas 里的像素不会自己变色。所以补了一个观察器监听属性变化：

```js
new MutationObserver(function () { repaint(); })
  .observe(document.documentElement, { attributes: true, attributeFilter: ['data-theme'] });
```

这里也翻过一次车：最初把观察器挂在动效初始化后面，遇到 `prefers-reduced-motion` 时代码提前 `return` 了，结果开了「减少动效」的用户一点切换主题，页面控件全变色了，背景却纹丝不动。后来把主题观察器和 `resize` 监听都提到了动效分支前面，保证任何偏好下主题切换都能同步重绘。

## 玻璃层与降级

CSS 端准备了两套变量（`:root` 默认暗色，`:root[data-theme="light"]` 覆盖），玻璃容器由半透明底色、`backdrop-filter: blur()` 和内外阴影组成。

样式只加在首页列表卡、目录卡、标签 chip、上下篇导航和分享按钮上；文章正文、顶栏、页脚、归档、标签列表和搜索页保持透明，直接浮在噪声场上。首页卡片范围用一条 `:has()` 收窄，利用首页 `.main` 含有 `.first-entry` 的特征排除置顶介绍块：

```css
body.list .main:has(> .first-entry) > *:not(.first-entry) { /* 玻璃样式 */ }
```

模糊渲染后的最终画面做过像素采样检查，暗色和亮色模式下正文的对比度都能稳过 WCAG AA（4.5:1）。降级样式按三层处理：

| 场景 | 处理 |
| --- | --- |
| 浏览器不支持 `backdrop-filter` | 卡片底色不透明度提到 0.94，关闭毛玻璃模糊 |
| 用户偏好减少透明度 | 卡片底色不透明度提到 0.92 并关闭 `backdrop-filter`，底层画布模糊从 48px 加大到 64px，光晕透明度降到 0.5 |
| 打印 | 隐藏背景画布与光晕，卡片还原成普通纸面 |

## 成本

- 代码量：JS 单文件 455 行，压缩后约 **6.1KB**，配套 CSS 约 186 行，零外部依赖
- 耗时：1440×900 视口下初始化噪声场与预计算数组约十几毫秒，之后单次 canvas 重绘只需 **2~3ms**，配合动态节流占用很低
- 触屏设备：虽然触摸滑动时同样会触发 `pointermove`，但因为 `(pointer: fine)` 不成立，平时不会开启空闲自动漂移，默认只保留静态首帧，日常几乎没有额外开销
- 无网络请求，构建产物只多一个 JS 文件和一个 CSS 文件

## 小结

这版背景和等高线那篇共用了同一套 `mulberry32 + simplex + fBm` 噪声函数，只是等高线是从高度场里抽线段，这里则直接把高度场叠上光斑画成低分辨率底图，再交给浏览器放大和模糊。把重计算放在低分辨率初始化里、日常动画走节流和合成器属性，即使没有显卡加速也能跑得比较轻。
